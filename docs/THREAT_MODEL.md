# BondAI Threat Model

| Threat Category | Attack Vector & Risk | Implemented Mitigation | Residual Risk / Production Prerequisite |
| :--- | :--- | :--- | :--- |
| **Account Takeover (ATO)** | Credential stuffing, brute-force password guessing, session hijacking via XSS or stolen refresh token. | Argon2id password hashing; per-account lockout after repeated failures; HTTP-only short-lived access JWT (15m) + rotating refresh JWT (7d) stored as SHA-256 hash in `user_sessions` with reuse detection revoking all user sessions; suspicious IP/UA anomaly notifications; optional TOTP 2FA (mandatory for admins). | Local email verification codes return only in `development` mode; production requires a transactional email provider (SES/Postmark/Resend) over TLS + DKIM/SPF/DMARC. |
| **Malicious or Compromised Admin** | Privileged insider attempting to read private dating conversations or alter limits unlogged. | E2EE Signal Protocol ciphertexts stored server-side only; zero admin private-key escrow; `requireAdmin` enforces both `role === 'admin'` AND active `mfaVerified: true`; zero-PII audit trail (`audit_logs`). | A malicious admin with runtime host access could tamper with frontend JS served to future visitors unless SRI/immutable container digests + Binary Authorization are enforced on Cloud Run. |
| **Database Breach** | Exfiltration of user table (`email`, `name`, `date_of_birth`, passwords). | Sensitive identity fields encrypted with AES-256-GCM (`v1:iv:tag:ct`); email lookup via keyed HMAC-SHA256 blind indexes; Argon2id hashes; chat content unreadable without Signal device private keys. | Discovery profile fields (display name, bio, interests, quiz vector) remain server-decryptable for matching. Production must mount master keys from Google Cloud KMS / Secret Manager rather than static env files. |
| **Impersonation & Underage Access** | Minors (<18) registering or bad actors catfishing / spoofing profiles. | Server-side DOB age check rejects anyone under 18 (`403 Forbidden`); Blind Connect hides photos (`403`) until mutual reveal; Safety Center report queue + suspension + block controls. | Self-attested DOB without government ID verification cannot stop deliberate age misrepresentation; optional Age/ID KYC verification partner recommended before public launch. |
| **XSS, CSRF & Injection** | Stored script payloads in profile/media uploads, cross-site state-changing requests, SQL/NoSQL query operator injection. | Helmet CSP (`defaultSrc: 'self'`); React auto-escaping; custom CSRF protection (`Origin`/`Referer` + `X-Requested-With: BondAI-Client` + `SameSite` cookies); strict Zod schema validation rejecting operator objects (`{$gt: ...}`); parameterized SQL queries; magic-byte upload inspection blocking SVG/HTML. | Legacy browsers without `SameSite=None; Partitioned` fallback rely on origin checks; regular OWASP ZAP & `npm audit` scans required in CI. |
| **Stalking & Location Exposure** | Extracting exact home coordinates or probing hidden Blind Connect photos via direct ID enumeration. | BondAI stores only user-chosen city/region text (no GPS lat/long stored); `share_approx_location` can hide even city text; `/api/profiles/media/:mediaId` verifies match state and returns `403` whenever Blind Connect `photos_revealed !== 1` or user is blocked. | Uploaded user photos may contain EXIF camera metadata unless stripped via Sharp/ImageMagick pipeline in object storage ingestion. |
| **Encryption Key Loss / MITM** | Browser IndexedDB wiped or a compromised server swaps prekey bundles silently. | `signal_identity_changes` table logs identity-key changes and warns chat partners; 60-digit Signal Safety Number (`FingerprintGenerator(5200)`) lets users verify out-of-band; Privacy Policy explicitly warns about local-key recovery limits. | If a user clears browser storage without multi-device linking, historical messages cannot be recovered. |
